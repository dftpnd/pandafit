# PandaFit — дизайн

Дата: 2026-08-31
Статус: утверждён к реализации

## 1. Задача

Подогнать видеофайл под ёмкость оптического диска и записать его, не гадая и не
переделывая по три часа. Пользователь открывает файл, видит все дорожки, решает
что выбросить, что пережать и где обрезать титры, всё время наблюдая точную
оценку итогового размера относительно ёмкости болванки. Программа объясняет
цену каждого решения в момент его принятия.

Мотивирующий случай: UHD-ремукс 61.9 ГБ с семью звуковыми дорожками, из которых
три — DTS-HD и TrueHD по ~4.3 ГБ. Целевая болванка BD-R DL 50.05 ГБ. Выброс
лишних дорожек решает задачу без перекодирования видео вообще — но это неочевидно,
пока не увидишь разбивку по потокам.

## 2. Границы

Входит:

- разбор файла на дорожки, показ их параметров и веса
- удаление дорожек
- перекодирование аудио (смена кодека и битрейта)
- перекодирование видео (смена кодека, разрешения, битрейта)
- обрезка по времени (титры, вступление)
- оценка итогового размера с интервалом достоверности
- объяснение последствий каждого решения
- сборка результата в MKV
- прожиг на диск в приводе

Не входит:

- сборка ISO-образа (повторный прожиг и верификация образа не нужны)
- смена контейнера (выход всегда MKV)
- автоподбор параметров, пресеты, очередь файлов, встроенный плеер
- работа с BDMV-структурой и ISO как источником

## 3. Ключевые решения

| Решение | Выбор | Причина |
|---|---|---|
| Язык и GUI | Rust + egui | один бинарник без зависимостей, таблицы и ползунки из коробки |
| Движок | внешние CLI за слоем абстракций | все возможности ffmpeg сразу, отлаживается копипастом команды |
| Оценка размера | арифметика по битрейтам + запас | мгновенный отклик на движение ползунка |
| Видео при перекоде | целевой битрейт (ABR + VBV), не CRF | размер должен быть предсказуем до запуска |
| Dolby Vision | сохраняем через dovi_tool + x265 | входит в v1 |
| Контейнер выхода | MKV | единственный, кто нормально держит DV, TrueHD и множество дорожек |
| Прожиг | growisofs | уже в системе, умеет UDF и файлы >4 ГБ |

## 4. Архитектура

### 4.1. Крейты

Workspace из трёх крейтов, зависимости строго в одну сторону:

```
pandafit-app    egui UI, оркестрация, внедрение зависимостей
     |
     v
pandafit-media  адаптеры: ffprobe, ffmpeg, dovi_tool, mkvmerge, growisofs, привод
     |
     v
pandafit-core   домен: ноль I/O, ноль ffmpeg, ноль egui
```

`core` не знает о существовании ffmpeg. Следствие: весь домен тестируется без
запуска единого процесса.

### 4.2. Доменная модель (`pandafit-core`)

| Тип | Ответственность |
|---|---|
| `MediaInfo` | результат зондирования: длительность, дорожки, цветовые данные |
| `Track` | один поток; знает свой битрейт и умеет `bytes_for(range)` |
| `ColorInfo` | `Sdr` / `Hdr10 { mastering, cll }` / `DolbyVision { profile, has_hdr10_base }` |
| `Plan` | решение пользователя: действие на каждую дорожку, диапазон времени, цель |
| `TrackAction` | `Copy` / `Transcode(CodecSpec)` / `Drop` |
| `Target` | целевая ёмкость в байтах + источник (привод / пресет / вручную) |
| `Estimated<T>` | значение с интервалом и `Confidence` (`Exact` / `Sampled` / `Guessed`) |
| `SizeBreakdown` | оценка, разложенная по дорожкам, каждая как `Estimated<u64>` |
| `Note` | одно объяснение: `Info` / `Warning` / `Blocker`, текст, привязка |
| `Step` | один шаг исполнения: команда, описание, способ снять прогресс |

### 4.3. Три чистые функции над `Plan`

```rust
fn estimate(&MediaInfo, &Plan) -> SizeBreakdown
fn explain (&MediaInfo, &Plan) -> Vec<Note>
fn compile (&MediaInfo, &Plan) -> Vec<Step>
```

Единый источник правды: оценка, объяснения и запускаемые команды выводятся из
одной структуры и не могут разойтись. Каждая функция имеет одну причину для
изменения (SRP) и свой независимый набор тестов.

### 4.4. Точка расширения — кодеки

Кодеки будут добавляться, поэтому не `match` по перечислению, размазанный по трём
файлам, а трейт с реестром:

```rust
trait CodecProfile {
    fn id(&self) -> &str;
    fn kind(&self) -> TrackKind;
    fn estimate_bps(&self, src: &Track, opts: &Opts) -> Estimated<u64>;
    fn args(&self, src: &Track, opts: &Opts) -> Vec<String>;
    fn notes(&self, src: &Track, opts: &Opts) -> Vec<Note>;
}
```

Добавление Opus — новый тип и одна строка регистрации; `estimate`, `explain` и UI
не меняются (OCP, Polymorphism).

### 4.5. Адаптеры (`pandafit-media`)

Узкие трейты вместо одного сервиса (ISP), у каждого свой фейк в тестах (LSP):

| Трейт | Реализация | Фейк в тестах |
|---|---|---|
| `MediaProbe` | `FfprobeProbe` | `FakeProbe` с записанным JSON |
| `BitrateProfiler` | `FfprobeSampler` | профиль из фикстуры |
| `ThumbnailSource` | `FfmpegThumbs` | заглушки-картинки |
| `JobRunner` | `ProcessRunner` | `ScriptedRunner` с заданными событиями |
| `DiscDevice` | `SgDiscDevice` + `GrowisofsBurner` | `FakeDisc` |

### 4.6. Слой приложения (`pandafit-app`)

Единственный тип `Session` принимает все действия пользователя и держит состояние
(GRASP Controller). Виджеты egui не запускают процессы и не считают байты — они
рисуют `Session` и шлют ему события. `PlanCompiler` и `JobRunner` — Pure
Fabrication: сущностей нет в предметной области, они существуют ради развязки
домена и процессов. Конкретные реализации адаптеров внедряются в `main` (DIP).

## 5. Оценка размера

```
итог = Σ байты_дорожек
     + накладные MKV   (~0.5% payload + 2 МБ)
     + метаданные UDF  (~8 МиБ, округление до сектора 2048 Б)
     + страховой запас (2% ёмкости)
```

### 5.1. Источник битрейта исходной дорожки

По убыванию достоверности, каждый несёт `Confidence`:

1. тег `BPS` в MKV — точно
2. `bit_rate` потока — точно для CBR
3. сэмплирование пакетов через `ffprobe -read_intervals` — ±3–5%
4. прикидка по кодеку и числу каналов — ±20%, помечается явно

Итоговая оценка — точка с интервалом; интервал наследуется от худшего слагаемого.

### 5.2. Профиль битрейта и обрезка

Линейная оценка экономии от обрезки («отрезали 8 из 115 минут — минус 7%») врёт
в опасную сторону: титры темнее и статичнее среднего кадра, их реальный вес в
разы ниже. Обещанная экономия не наступит, и файл не влезет уже после энкода.

Поэтому после открытия файла в фоне строится профиль битрейта: `ffprobe`
сэмплирует по 2 секунды раз в минуту и суммирует размеры пакетов. Экономия
считается интегралом под этой кривой. Тот же проход отдаёт кадры для полосы
миниатюр — один скан, два потребителя. До готовности профиля показывается
линейная оценка с пометкой «уточняется».

### 5.3. Перекодирование

- видео: целевой битрейт с VBV-ограничителем, размер ±2%
- аудио CBR (AC3, E-AC3, Opus): `битрейт × длительность`, точно
- FLAC: непредсказуем (50–70% от PCM), показывается диапазоном
- субтитры: SRT — фактический размер файла; PGS — по битрейту

### 5.4. Ёмкость цели

Берётся из привода через `READ FORMAT CAPACITIES` (точное число секторов
вставленного диска), а не из таблицы номиналов. Пресеты (BD-R 25/50/100,
DVD 4.7/8.5) и ручной ввод — запасные варианты, когда привода нет.

### 5.5. Светофор

- зелёный: верхняя граница интервала ниже ёмкости
- жёлтый: точка ниже, верхняя граница выше
- красный: точка выше ёмкости, показывается размер лишнего

## 6. Исполнение

### 6.1. Цепочки шагов

Видео копируется: один шаг ffmpeg (ремукс).

Перекод без сохранения DV: один шаг ffmpeg с `hevc_nvenc` или `av1_nvenc`.

Перекод с сохранением DV:

```
1. dovi_tool extract-rpu                       -> rpu.bin
2. [только при обрезке] dovi_tool editor       -> rpu.trimmed.bin
3. ffmpeg + libx265 -x265-params
     dolby-vision-rpu=<rpu>:dolby-vision-profile=8.1
4. mkvmerge — сборка финального MKV
```

RPU содержит запись на каждый кадр и обязан совпасть с видео покадрово. При
одновременной обрезке RPU режется тем же диапазоном (шаг 2), иначе энкодер
падает или метаданные рассинхронизируются.

Прожиг: `growisofs -Z /dev/sr0 -udf -allow-limited-size`, опционально сверка
sha256 прочитанного с диска.

### 6.2. Точность обрезки

При `-c copy` рез возможен только по ключевым кадрам (в UHD-ремуксах — раз в
2–5 секунд). Программа находит ближайший ключевой кадр и показывает фактическую
точку реза рядом с запрошенной. При перекоде рез точный.

### 6.3. Прогресс

`ffmpeg -progress pipe:1 -nostats` выдаёт `out_time_us`, `total_size`, `speed`
раз в секунду. Из `total_size` известен фактический вес уже записанного, из
профиля битрейта — ожидаемый на этот момент. Их отношение даёт живой прогноз
итогового размера: расхождение с бюджетом видно на пятнадцатой минуте, а не на
четвёртом часу. Прогресс x265, dovi_tool и growisofs снимается с их stderr.

### 6.4. Отмена и восстановление

Каждый шаг — отдельная группа процессов; отмена это SIGTERM, через 5 секунд
SIGKILL. Промежуточные файлы (`rpu.bin`, сырой `.hevc`) лежат в рабочей папке
рядом с целью и переживают падение: повторный запуск подхватывает готовый
`.hevc`, а не начинает четырёхчасовой энкод заново. Состояние — `job.json` там же.

### 6.5. Preflight

Перед запуском проверяется и показывается списком:

- `ffmpeg` и `ffprobe` — всегда
- `dovi_tool` и `mkvmerge` — только для DV-режима; при отсутствии выводится
  команда установки (сейчас на машине их нет)
- инициализация NVENC
- свободное место: обычный режим требует размер результата, DV-цепочка примерно
  вдвое больше из-за промежуточного сырого потока
- доступ к `/dev/sr0` и наличие чистой болванки

### 6.6. Ошибки

`thiserror` в core, `anyhow` на границе приложения. Каждый шаг хранит последние
~200 строк stderr, доступные по кнопке «показать лог». Кнопка «скопировать
команду» позволяет воспроизвести любой шаг в терминале вручную.

## 7. Интерфейс

Одно окно, три состояния: пусто -> настройка -> выполнение.

### 7.1. Экран настройки

```
+---------------------------------------------------------------------+
| Тор.2011.Hybrid.UHD.Blu-Ray.Remux.2160p.mkv    1:54:50   61.91 ГБ   |
| Цель: [ Диск в приводе — BD-R, 25.03 ГБ  v ]                        |
+----------------------------------------------+----------------------+
| x видео  HEVC 2160p HDR10+DV   54.9M         |  БЮДЖЕТ              |
|          [ Копировать          v ]  47.25 ГБ |                      |
| x аудио  AC3 5.1  rus  Dub      640k         |  [!] 48.60 / 25.03   |
|          [ Копировать          v ]   0.55 ГБ |  лишних 23.57 ГБ     |
| o аудио  DTS-HD 7.1 rus Гаврилов 5.0M        |                      |
|          [ AC3 640k            v ]   0.55 ГБ |  видео    47.25 (!)  |
| o аудио  TrueHD 7.1 eng         4.9M         |  аудио     1.10 (!)  |
|          [ Удалить             v ]      —    |  субтитры  0.01 (!)  |
| x субтитры x7                                |  контейнер 0.24 (~)  |
+----------------------------------------------+                      |
| [кадр][кадр][кадр][кадр][кадр][кадр][кадр]   |  предупреждения      |
| 00:00 |--------------------------| 01:52:00  |  и запреты           |
|       обрезка: 00:00 -> 01:52 (-2:50)        |                      |
|                                              |                      |
|                          [ Собрать ] [ Собрать и прожечь ]          |
+----------------------------------------------+----------------------+
```

Строка видео при выборе «Перекодировать» разворачивается: кодек (HEVC NVENC /
HEVC x265+DV / AV1 NVENC), разрешение, ползунок битрейта. Цифра бюджета
пересчитывается на каждом кадре отрисовки — тянешь ползунок и видишь, как
красное становится зелёным.

### 7.2. Объяснения

Три уровня, все — отрисовка `Vec<Note>` из `explain(&Plan)`. Текст не зашит в
виджеты.

| Уровень | Где | Пример |
|---|---|---|
| Info | иконка у поля, по наведению | «Битрейт — сколько данных в секунду. Вдвое меньше битрейт ≈ вдвое меньше файл, но появляются квадраты на движении» |
| Warning | панель бюджета, как следствие выбора | «AC3 не умеет 7.1 — дорожка сложится в 5.1»; «x265 сохранит Dolby Vision, но энкод займёт ~5 ч вместо 25 мин» |
| Blocker | там же, гасит кнопку «Собрать» | «Dolby Vision Profile 5 нельзя перекодировать: без RPU цвет развалится» |

Info учит, Warning называет цену уже принятого решения, Blocker не даёт
выстрелить в ногу.

## 8. Тестирование

- `core` — обычные модульные тесты на фикстурах `MediaInfo`; проверяется, что
  оценка и скомпилированные команды сходятся с ожидаемыми
- снапшот-тесты на `compile`: строка команды ffmpeg фиксируется и меняется только
  осознанно
- `media` — тесты на разбор реального вывода `ffprobe` и `ffmpeg -progress`,
  записанного в файлы-фикстуры
- сквозной тест: короткий сгенерированный файл (`testsrc` + два аудиопотока),
  прогон полного цикла сборки, сверка фактического размера с предсказанным
- прожиг в автотестах не участвует: `DiscDevice` подменяется фейком
